# 세일즈맵 GitBook 가이드북 작성 스킬

세일즈맵 개발자 센터(docs.salesmap.kr) 고객용 문서를 작성/갱신할 때 이 규칙을 따른다.
확립일: 2026-07-16 (getting-started.md·tools.md 작업 기준)

## 0. 철칙

1. **코드가 원본이다.** 도구명·파라미터·enum 값은 반드시 `src/tools/*.ts`의 zod 스키마에서 추출해 대조한다. 기억이나 구버전 문서로 쓰지 않는다. 파라미터 표 하나하나가 실제 구현과 1:1이어야 한다.
2. **기존 문서 형식을 존중한다.** 갱신 작업이면 먼저 기존 페이지를 가져와(`https://docs.salesmap.kr/<경로>.md` — URL 끝에 `.md` 붙이면 마크다운 원문) 구조를 파악하고, 그 골격 위에서 내용만 현행화한다.
3. **결과물은 `docs/`에 커밋**하고, GitBook에는 사용자가 Import로 올린다 (Git Sync 아님 — docs/에 내부 문서가 섞여 있어 전체 동기화 금지).

## 1. 문서 구조 관례

- 메뉴: `AI 연결 (MCP)` > 시작하기 / 도구 목록 / 활용 가이드
- **공통 내용은 탭 밖, 플랫폼별 차이만 탭 안**. 예: 시작하기 = 토큰 준비(공통) → 플랫폼 탭 → 연결 확인(공통) → 문제 해결(공통)
- 도구 목록 = 카테고리 `###` → 도구 `####` → 한 줄 설명 → 파라미터 표 → **사용 예시** → 끝에 도구 권한 표(읽기/쓰기/삭제)
- 파라미터 표 컬럼: `| 파라미터 | 타입 | 필수 | 설명 |` — 필수는 ✅ / 조건부 필수 / (빈칸)
- 긴 참조 목록(연산자 표 등)은 `<details><summary>` 접기
- 섹션 구분은 `***`

## 2. GitBook 문법

```
{% tabs %}
{% tab title="Claude" %} ... {% endtab %}
{% tab title="ChatGPT" %} ... {% endtab %}
{% endtabs %}

{% hint style="info" %} 참고 정보 (파란 박스) {% endhint %}
{% hint style="warning" %} 주의사항 (노란 박스) {% endhint %}
```

- 탭 제목은 플랫폼/도구 이름 그대로 (Claude, ChatGPT, Gemini, Claude Code, Codex, Antigravity, 기타)
- hint 남용 금지 — 페이지당 2~4개. 진짜 함정(토큰 재발급 시 연동 끊김 등)에만 warning
- 이 문법은 GitHub에선 렌더링 안 됨 — 정상이며 GitBook Import 시 블록으로 변환됨

## 3. 톤 & 용어

- **한글 우선, 고유명사만 영문** (Claude, MCP, API). 병기 금지 — "웹훅(Webhook)" ❌ → "웹훅" ⭕
- 메뉴/제목 용어: `AI 연결 (MCP)` / `시작하기` / `도구 목록` / `활용 가이드` / `API 레퍼런스` / `웹훅`
- 독자는 비개발자 영업팀 포함 — 설명은 짧은 완결 문장, 개발 은어 금지. 단 터미널 탭(Claude Code·Codex 등)은 개발자 대상이라 명령어 중심으로 간결하게
- 사용 예시는 기능 나열이 아니라 **실제 대화 문장**으로: "이번 달 생성된 딜 중 상태가 Won인 것 검색해줘"

## 4. 고정 사실 (문서에 반복 등장)

- 서버 주소(신규 안내): `https://mcp.ai.salesmap.kr/mcp` — 구주소(`salesmap-mcp.vercel.app/api/mcp`)도 계속 동작하므로 기존 사용자 재설정 불필요 문구 유지
- 토큰 위치: 세일즈맵 → 설정 → 개인 → 연동 → API. **있으면 복사, 없을 때만 생성** (재발급 시 기존 연동 전부 끊김 — warning 처리)
- 토큰은 발급자 권한을 따름 (읽기 전용 사용자는 쓰기 도구 불가)
- API 제공 플랜: Free 또는 Professional 이상 (Starter 제외)
- 연결 방식 원칙: 앱(Claude·ChatGPT·Gemini)은 커넥터+브라우저 토큰 입력 / **터미널은 토큰 직접 지정만 안내** (OAuth 대안 쓰지 않음)
- mcp-remote 브리지는 신규 안내에서 사용 금지 (기존 고객 호환용으로만 서버가 지원)
- Gemini는 미국 한정 — "국내 오픈 시 업데이트 예정" 문구
- 연결 확인 표준 문구: "세일즈맵에서 내 정보 조회해줘"

## 5. 작업 절차

1. 기존 페이지 원문 확보: `curl https://docs.salesmap.kr/<경로>.md` (경로는 `https://docs.salesmap.kr/sitemap.md`에서 검색)
2. 코드에서 현행 스펙 추출 (도구 문서라면 zod 스키마 전수 대조, 총 개수 카운트 포함)
3. 기존 형식 골격 유지 + 내용 현행화 (구버전 오타도 이때 수정)
4. `docs/<파일명>.md` 저장 → 브랜치 → PR → 머지
5. 사용자에게 변경 요약 표 + GitHub 링크 + "GitBook Import로 교체" 안내
