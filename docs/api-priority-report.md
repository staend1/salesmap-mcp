# API 개선 우선순위 리포트

> 대상: 세일즈맵 API·백엔드 팀 / 목적: MCP(AI 연동) 관점에서 필요한 API 개선을 **우선순위와 실사용 근거**로 보고
> 원장: [salesmap-api-issues.md](salesmap-api-issues.md) — 이슈의 기술 상세·재현·우회 구현은 원장 참조, 이 문서는 판단용 요약만
> 근거 데이터: MCP 텔레메트리 (베타 워크스페이스 ~77개, 2026-06-01~07-23, 24K+ 호출)
> 최신화: 2026-07-23 / 우선순위 판정: 초안(AI) — 확정 전

---

## 우선순위 기준

**1차 기준 = MCP 레이어에서 우회 가능한가.** 우회 불가한 것이 항상 우회 가능한 것보다 위.

| 등급 | 기준 |
|---|---|
| **P0 (상급)** | **MCP로 우회 불가** + 실사용 로그에서 고통이 정량으로 반복 확인됨. 지금 고객이 겪는 중 |
| **P1 (상급)** | **MCP로 우회 불가**로 업무 플로우를 완결 불가로 만듦. 빈도는 낮아도 구조적 차단 |
| **P2 (중급)** | 우회는 되지만 **내부 비효율 발생** (예: fieldList 타입 매칭처럼 매 호출 스키마 조회 API 콜 추가) |
| **P3 (하급)** | 우회되고 **비효율도 거의 없음**. 뉴버전 API 설계 시 반영하면 되는 정리 항목 |

즉 P0/P1은 "우회 불가"(P0는 로그로 아픔 확인, P1은 플로우 차단), P2/P3은 "우회 가능"(P2는 비용 있음, P3은 거의 없음)으로 갈린다.
보조 축: 실사용 빈도(로그) · 막힌 업무의 가치.

## P0 — 지금 고객이 겪는 중

### [P0] Batch Create/Update API — "레코드 N건 일괄 생성·수정"

- **원장**: #1
- **요청**: `POST /v3/object/create`·`update`에 다건 입력 (최대 100건), create는 association 동시 세팅 포함
- **실사용 증거** (create/update 전체 2,049콜 분석, 6/1~7/23):
  - **86%(1,759콜)가 "5건 이상 연속 버스트"** — 이 도구들의 실제 용도가 사실상 배치 작업
  - 최악 사례: 고객 598명에 불리언 필드 1개 켜기 = **598콜 연속, 19.8분** (Fast campus, 6/12). 3일 뒤 225건 재분류로 반복
  - 반복 업무 사례: 한 계정이 **7월에만 버스트 12회** (교육 프로그램 선발/참여 관리 — 매주 도는 정기 업무가 매번 수십 콜)
  - 임포트 사례: 회사 37건 연속 생성 4.6분, 실패 3건 (SK렌터카)
- **현재 우회와 비용**: 단건 도구 반복 호출(사용자가 분 단위 대기 + LLM 왕복 토큰 낭비) 또는 run-script 순회(50초 상한·가드레일로 쓰기엔 소극적). 버스트 동안 우리 스로틀이 워크스페이스 rate limit(100/10초)의 **~83%를 지속 점유** → 같은 워크스페이스 동료의 AI 사용까지 밀림
- **기대 효과**: batch 100 기준 **1,759콜 → 63콜 (28배)**, 121분 → 1~2분. 쿼타 점유 문제 동시 해소

### [P0] Activity(타임라인) 배치 조회 — "레코드 N건의 활동을 한 번에"

- **원장**: #28
- **요청**: `/v3/object/read`에 activity 인라인 파라미터, 또는 다건 objectId를 받는 배치 activity 엔드포인트
- **실사용 증거** (6월 로그):
  - list-engagements가 **전 도구 중 최다 호출(6,703콜)**, `engagements→engagements` 연속 전이 6,385회 = 레코드별 N회 반복이 구조적
  - p90 **7.9초**, 5초 초과 20.9%, **429 rate limit 52건 전부 이 도구에서 발생**
- **현재 우회와 비용**: 유형 필터·limit·응답 경량화로 완화했지만(2026-07) **N레코드=N콜 구조 자체는 백엔드 확인 결과 해소 불가** (activity API가 단일 objectId만 수용)
- **기대 효과**: "리드 87건 팔로업 현황" 같은 분석이 87콜→1콜. 429·지연·쿼타 점유 동시 해소

## P1 — 플로우 완결을 막는 공백

### [P1] 견적서 발행 API — "생성까지만 되고 발송을 못 함"

- **원장**: #29
- **요청**: `POST /v2/quote/{id}/publish` (공유 링크 반환) 또는 생성 시 `publish: true` 옵션
- **실사용 증거**: 실측(2026-07) — API 생성 견적서는 `공유 링크`가 null, 발행 관련 엔드포인트 전무. 발행은 GUI 전용
- **현재 우회와 비용**: 없음 — "AI가 견적서 만들어 고객에게 발송"이 **구조적으로 완결 불가**. 생성 후 사람이 GUI에서 발행+발송을 이어받는 반쪽 자동화
- **기대 효과**: 견적 플로우(생성→발행→이메일 발송)가 API 조합으로 완결 — 세일즈 핵심 시나리오의 자동화 개방

### [P1] 커스텀 오브젝트 검색 — "커오는 조건 검색이 안 됨"

- **원장**: #4-5
- **요청**: `POST /v2/object/{type}/search`(또는 v3 검색)의 커스텀 오브젝트 지원
- **실사용 증거**: 커오를 메인 워크플로우로 쓰는 팀(티켓 관리 등)이 조건 검색 대신 **전량 조회 후 클라이언트 필터**로 우회하는 패턴 관찰 (run-script `getAll` 사용례 다수)
- **현재 우회와 비용**: 전량 스캔 — 레코드가 수백 건이면 낭비, 수천 건이면 사실상 불가
- **기대 효과**: 커오 기반 업무(티켓·계약·정산)가 기본 오브젝트와 동급으로 검색 가능

### [P1] 레코드 병합 API

- **원장**: #24
- **요청**: `POST /v2/object/{type}/merge` (survivor 지정 + 연결 이전)
- **실사용 증거**: 한 고객이 회사 중복 정리를 위해 run-script **77회, 7시간**에 걸쳐 병합 로직을 자체 조립 (연결 고객·딜 재연결 + [DEL] 마킹, 2026-07-06)
- **현재 우회와 비용**: 공개 API 조합으로 가능은 하나 위험한 대량 쓰기를 매번 AI가 즉석 작성 — 실수 시 데이터 꼬임
- **기대 효과**: CRM 위생의 최다 빈도 작업(중복 정리)이 안전한 1콜로. MCP에 merge 도구로 노출 가능

### [P1] 그 외 우회 불가 (빈도·가치 재판단 대기)

| 항목 | 원장 | 우회 불가 사유 |
|---|---|---|
| 이메일 본문 미제공 | #9 | activity/email 응답에 제목·메타만 — 본문 자체가 안 와서 이메일 내용 분석 불가 |
| 필드 수정 API 부재 | #19 | 옵션 값 추가·라벨 변경이 UI 전용 — "카테고리에 옵션 추가" 자동화 차단 |

## P2 — 우회되지만 내부 비효율 발생

| 항목 | 원장 | 요청 | 우회 비용 |
|---|---|---|---|
| properties 기반 쓰기 (타입 키 제거) | #2 | HubSpot식 평탄 name→value 수용 (2026-07 공식 문서 재검증) | `resolveProperties()`가 **매 쓰기마다 스키마 조회 API 콜 추가** (fieldList 타입 매칭). 공식 MCP·직접 API 사용자에겐 그대로 노출되는 부담 |
| Search 응답 필드 선택 | #4-3 | search에 `properties[]` 지원 | search→batch-read **2단 호출(N+1 패턴)** 강제 |

## P3 — 우회되고 비효율도 거의 없음 (뉴버전 정리 대상)

| 항목 | 원장 | 요청 | 비고 |
|---|---|---|---|
| 연결 문법 이중성 (기본=top-level / 커스텀=필드) | #3 | 뉴버전에서 연결 포함 전부 `properties`로 통일 (Salesforce 축) | 커스텀 연결은 이미 우회 완료. 기본 연결(회사·고객)만 `TOP_LEVEL_ONLY` 확장하면 흡수 — 코드 십수 줄, 비효율 없음 |
| 노트 생성 메타 지정 | #12 | 전용 노트 생성 API (날짜·유형·담당자) | update의 memo로 생성은 됨, 메타만 미지정 |
| Association 대량 생성 전용 API | #20 | (선택) 연결만 대량 처리하는 엔드포인트 | update의 관계 필드로 우회 가능 — batch update가 관계 필드 수용하면 자동 커버, 별도 API 불필요할 수 있음 |
| 429 표준 헤더 | #28 부수 | `Retry-After` 헤더 | body 텍스트 파싱으로 대응 완료 |
